# Smriti 2026 ID-card mail merge

This package turns attendee JSON into a multipage PDF: one portrait CR80 card per record.

The production page is exactly `54 x 85.6 mm` (`153.070866 x 242.645669 pt`). There is no bleed, printer margin, crop mark, or surrounding whitespace. The renderer keeps protected content inside a 2 mm internal safe area.

## Input

```json
{
  "schema_version": 1,
  "cards": [
    {
      "name": "SAMPLE PERSON",
      "branch": "CIVIL ENGINEERING",
      "photo_path": "../assets/sample-photo.webp",
      "attendee_id": "0001"
    }
  ]
}
```

`attendee_id` is the system attendee ID. It must be a string of exactly four ASCII digits; leading zeroes are significant. IDs are never generated or coerced by the renderer. Duplicate IDs, missing fields, missing photos, corrupt photos, and text that cannot fit fail the complete batch before a PDF is written.

Relative photo paths resolve from the JSON file's directory. Photos are EXIF-oriented, decoded with Pillow, and deterministically top-biased cropped into the rounded coral panel. The supplied transparent portrait is used as-is as the sample asset.

## Commands

From this directory:

```bash
uv run idcards.py prepare-assets
uv run idcards.py validate fixtures/attendees.json
uv run idcards.py render fixtures/attendees.json --output output/attendees.pdf
uv run idcards.py proof fixtures/attendees.json --output-dir proof --dpi 300
uv run python -m unittest discover -s tests -v
```

`idcards.py` also carries inline PEP 723 dependency metadata, so it can be copied and run as a standalone script with `uv run --script idcards.py` when its `assets/` directory is kept beside it.

`render` writes the production PDF and a same-stem `.report.json`. `proof` writes a guided proof PDF plus rasterized proof pages. Guides are never included in the production PDF. The card has no lanyard slot; the full page is artwork.

The first `render` or `prepare-assets` run builds the normalized sheets and named crops under `assets/doodles-sheets/`, `assets/crops/`, and `assets/doodles-production/`. No image-generation service is needed at runtime.

## Package contents

- `idcards.py` - the complete deterministic renderer and CLI.
- `assets/` - the exact logo, sample transparent portrait, bundled fonts, college line-art source, and fixed-grid doodle source sheets.
- `fixtures/attendees.json` - a three-record sample mail merge using IDs `0001`, `0042`, and `9999`.
- `tests/` - regression checks for PDF geometry, fonts, IDs, backgrounds, assets, and excluded motifs.

To use real attendees, copy the fixture JSON, replace its `cards` array, and point each `photo_path` at the corresponding image. Keep each `attendee_id` as a quoted four-character string so leading zeroes survive JSON parsing.

## Asset policy

- `assets/smriti-logo.png` is the exact supplied RGBA logo and is not redrawn or regenerated.
- `assets/fonts/BarlowCondensed-Regular.ttf`, `assets/fonts/BarlowCondensed-Bold.ttf`, and `assets/fonts/BarlowCondensed-Black.ttf` are the exact embedded faces used by the renderer. Barlow Condensed was chosen to match the generated card's tight display typography; the static TTFs avoid synthetic PDF condensation and local-font dependencies.
- The bundled Barlow Condensed files come from the official Google Fonts repository: [regular](https://github.com/google/fonts/blob/main/ofl/barlowcondensed/BarlowCondensed-Regular.ttf), [bold](https://github.com/google/fonts/blob/main/ofl/barlowcondensed/BarlowCondensed-Bold.ttf), and [black](https://github.com/google/fonts/blob/main/ofl/barlowcondensed/BarlowCondensed-Black.ttf). They are licensed under the [SIL Open Font License 1.1](https://github.com/google/fonts/blob/main/ofl/barlowcondensed/OFL.txt), included as `assets/fonts/OFL-BarlowCondensed.txt`.
- `assets/sample-photo.webp` is the supplied transparent portrait.
- `assets/doodles-sprite-sheet.png` is the alpha-bearing reference sheet used only for the simplified college facade. `assets/crops/` is generated from it deterministically.
- `assets/doodles-sheets/hero-a-source.png`, `hero-b-source.png`, and `micro-source.png` are the imagegen batching sources. Hero A is the fixed four-quadrant sheet for friends, Kerala chaya glass, autograph book, and cassette; Hero B is the fixed four-quadrant sheet for compass, set-square, and the two paper planes; Micro is the fixed 3x2 sheet for hearts, stars, sparkle, plus, dot, and burst marks.
- `assets/doodles-sheets/hero-a.png`, `hero-b.png`, and `micro.png` are normalized RGB copies with every background pixel set to the exact card color (`#171B1B`). `assets/doodles-production/` is generated by fixed cell coordinates, trims only inside each declared cell, adds a clean opaque border, and derives terracotta micro variants without chroma-keying. `assets/doodles-production/manifest.json` records every source cell, foreground bounds, and output size.
- The active motifs include the larger chaya-kada tea glass, autograph book, horizontal cassette, four friends, one restrained heart, one college-zone paper plane, one sparkle, subdued compass/set-square marks at the bottom, plus marks, dots, and colored bursts. Plate-food, phone, calculator, CD, backpack, bus, ticket, iPod, and modern-electronics motifs are not rendered.
- Curved connective marks are drawn as native cubic PDF splines with vector stroke/dash operations. They remain sharp at print scale and are kept separate from the raster sprite sources.

The card itself is built with ReportLab canvas operations. Text, rules, the card background, the safe-area geometry, and the dynamic fields remain deterministic/selectable PDF content. The supplied logo and simplified college line art retain alpha; the active nostalgia doodles use the exact opaque card background by design.

## Output gate

The renderer verifies page count, portrait dimensions, rotation, MediaBox/CropBox/TrimBox/BleedBox equality, and embedded font programs before replacing the output path. The PDF is only replaced after those checks pass.

Before a real batch is released, print one physical test card at 100% / actual size. Direct-card printers can apply their own edge clipping or color conversion even when the PDF is geometrically correct.
